# 动效

静态界面能真实运行、布局和资源都稳定以后，再加动效。只要静态效果的任务，做到静态就停。

## 1. 先定方案

- 有单独安装的 `ui-motion-advisor` 技能时，开一个**不带制作历史**的新会话（或隔离的子 Agent）来判断：第一轮只给本页设计图、用户原话和明确的约束，判断哪些区域该动、主次和节奏；第二轮让它按交互走一遍（入口、操作、反馈、状态变化、退出）补漏，再合并。不要预先告诉它「这里不动」「只做微动」，也不要给旧方案和实现截图。
- 没装这个技能就自己按同样两步判断，并在结果里说明「没有独立判定」。
- 方案存在用户工程里（比如 `evidence/motion/<界面>/`），视觉首判、交互复查、合并结论分开保存。
- 参数微调（时长、缓动）、目的和主次不变的修复，直接沿用已有方案，只记下改了什么。

## 2. 写进 ui/

动效写成组件 XML 里的 `<transition>`（写法见 UI 开发规范第 6 节）：

- 入场动效：`<transition name="enter" autoPlay="true">`，界面创建时自动播放；旋转、换语言重建组件时会再播一次。
- `time`、`duration` 的单位是帧，不是毫秒（按工程帧率换算，FairyGUI 默认每秒 24 帧）；不要把毫秒直接填进去。
- 同一时间一个属性只由一个东西控制：已经用控制器的 gear 控制的属性，不要再用动效改。
- 代码里按条件播放、重播、放完通知：用动效名当绑定表的键，写 `playing`、`play`、`done`（MVC 开发规范第 6.4 节）；不要在 View 里绕过框架直接操作动效。界面被盖住时框架会暂停动效，关闭时停掉。
- 动效结束不能当作业务完成（发奖、扣钱、请求成功都以 Controller 的结果为准）。
- 按钮按下的反馈写 `downEffect="scale"`（框架带缓动地按下、回弹，不用写代码）。

### 2.1 跟代码补间怎么分工

用到运行时才知道的东西（新旧数值、截止时间、第几个、有几个、出了什么事），写代码：绑定里的 `roll` / `tick`，或者 View 里的 `this.tween`（MVC 开发规范第 16 节）。不用这些、怎么动都是固定的（入场、常驻的呼吸和闪烁、Model 一变就播一遍的固定反馈、按钮按下），写进 `ui/`：动效用 `playing` / `play` 绑定触发，按下用 `downEffect`。

- 代码里也能循环（`repeat: -1`），但固定的循环仍推荐写进 `ui/`：编辑器里能直接预览，改节奏不用改代码，好几个控件、好几段关键帧在时间轴上更好维护。要按序号错开、按数据定幅度的循环（一排点按序号起伏），用代码。
- 同一个控件的同一个属性只交给一方，两方都要动就套一层：外层归一方、里层归另一方（比如按钮本身归 `downEffect`，呼吸写在里面的 `body` 子组件上）。抢了同一个属性运行时报 `LGUI-RT-282`。
- 补间的终值尽量就是 `ui/` 里的样子（从偏移飞回原位、从 0 弹到 1）：旋转、换语言重建以后，放完留下的样子不带过去。

## 3. 验收

在 `lgui dev` 里按正常速度看一遍代表流程：打开、切换、提交结果、关闭。看动作能不能看清、主次和节奏对不对、文字能不能读、操作有没有被拖慢；再试中途打断、重新打开。截图只能证明终态，看不出节奏——没有连续播放看过的，结果里写「观感未验证」。
