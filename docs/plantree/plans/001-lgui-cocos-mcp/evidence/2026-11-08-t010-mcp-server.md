# 证据：T010 MCP server 落地 + Q5 收口（2026-11-08）

## 结论

M2 第二项落地：`lgui-cocos-mcp/mcp/server.mjs`——stdio 传输的最小 MCP server，把 lgui CLI 包装成 5 个白名单工具（check / ui_list / test / verify / cocos_export）。宿主形态与「包装而非新增命令」的边界由 [decisions/006](../decisions/006-mcp-server-hosting.md) 收口（**Q5 关闭**，open-questions 更新）。协议测试 5/5（`tests/unit/cocos/mcp-server.test.mjs`）。

## 实现

- **协议**：按行分隔 JSON-RPC 2.0（MCP stdio），手写 initialize / notifications/initialized / tools/list / tools/call / ping 与 -32601/-32700/-32603 错误处理。无 SDK 依赖；server 不写 stderr。
- **工具 = CLI 子进程**：`node plugin/tools/lgui.mjs <命令> --json`（cwd = LGUI 工程根，宿主按工程目录启动 server 或设 `LGUI_PROJECT_ROOT`）。CLI `--json`（`{ok, data, errors, summary}`）进 text content，`ok:false` → `isError:true`。口令只有 CLI 一份（草案的「两套口令漂移」警告落地为架构约束）。
- 测试：spawn 真 server 进程走完整握手；真工具调用（check 对 init 工程 ok、cocos_export 导出 init 工程到假 CC 工程 sceneCreated:true、非法目标透传 `LGUI-CLI-053`、未知工具 isError、未知 method -32601、server 零 stderr）。

## 过程排坑（MCP 包装层的两颗特有雷）

1. **CLI 子进程输出后不退出**：spawn 默认给子进程保持打开的 stdin pipe，而 CLI 侧有 stdin 监听——check 输出 JSON 且 exit 0 之后进程仍挂（child `close` 事件永不来）。修：spawn `stdio: ['ignore', 'pipe', 'pipe']`。这只修了 check 一类；export（OpenFairyGUI 链）、verify（dev server）仍有别的句柄不退——最终修法是 **runCli 收到完整结构化 JSON（单行含 `ok`）即结算并 `child.kill()`**，不依赖 close。对「不退出 CLI」的通用防御，unity 侧命令如接入同一 server 也被覆盖。
2. **测试断言**：正常路径现在显式带 `isError: false`（协议合法），断言从 `=== undefined` 放宽为 `!isError`。

## 范围（决策 006）

不做自由传命令的工具（`lgui_run <任意>` 安全面过大）；T011/M3 的启动游戏（Creator Play 控制）后续以新工具加进同一 server。dev 长驻类命令（`lgui dev`）不适合 MCP 同步调用，未列入。

node --test tests/unit/cocos/mcp-server.test.mjs          # 协议与工具 5/5
