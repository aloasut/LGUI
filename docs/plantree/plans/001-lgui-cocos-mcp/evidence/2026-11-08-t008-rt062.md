# T008 证据：binding-language 的 LGUI-RT-062 根因与修复（2026-11-08）

## 结论一句话

RT-062 不是绑定引擎或横竖版的差异，而是 **FairyGUI 按包名全局注册**：conf 页面在 T008b 之前的构建里先跑了 inventory 冒烟（Boot.ts 当时没有 `?conf=` 跳过），把 lgui-ui bundle 的 `Main` 包灌进全局注册表，conf 后端 `loadPackage('Main')` 见 `getByName('Main')` 已存在就静默返回，`create('Main','MainView')` 造出来的是 **inventory 版 MainView**（子控件 title/subtitle/bagEntry/…，没有 status）→ 绑定层 `resolve('status')` 报 RT-062。headless/h5 各有独立运行时，没有这个冲突，所以只有 cocos 失败。

## 证据链

1. **inventory 版 MainView 没有 status**：`examples/inventory/ui/assets/Main/MainView.xml` 的 displayList 是 title/subtitle/bagEntry/shopEntry/rewardEntry——对得上报错文本。
2. **触发时机**：068144c（01:32）**自己**往 Boot.ts 加了 `&& !new URL(location.href).searchParams.get('conf')`——说明观察到 RT-062 的那次运行发生在补丁落地前的构建上：conf 页面 + 无条件冒烟 = 冒烟先加载 lgui-ui 的 Common/Main。
3. **静默吞掉的路径**（修前）：`backends/cocos/platform/index.ts` 的 `resource.loadPackage` 开头 `if (fgui.UIPackage.getByName(name)) return;`——不校验这个包是不是自己加载的，谁先占住名字就用谁的。
4. **HEAD 上复现不了 RT-062**：重建后的 conf 页面（Boot.ts 跳过冒烟已生效）`lgui.ui.open(MainView)` 正常，绑定生效（status 文本=「点下面的按钮试试」）；`b.create('Main','MainView')` 与 `@portrait` 两版 childNames 都是 [bg, safe, title, status, button]。模板 `MainView@portrait.xml` 本来就有 status——「竖版缺键」的初始嫌疑排除。
5. **冲突机制实验复现**：在 conf 页面手动先加载 lgui-ui bundle 的 `Main` 包，再让 conf 后端 `loadPackage('Main')` → create 出的组件子控件为 inventory 版（title/subtitle/bagEntry…），绑定 status 必然 RT-062。

## 修复后仍然可复现的失败：LGUI-RT-011（setLanguage）

修完冲突后，binding-language 在 cocos 上走到 `t.setLanguage('en')` 报 `LGUI-RT-011 读不到界面包 bundle i18n`。根因是 **2e972c6 引入的回归**：bundleReady 参数化时把 setLanguage 从 `bundleReady()`（UI bundle）改成了 `bundleReady(i18nBase || 'lgui-ui')`——把翻译目录名 `'i18n'` 当成了 bundle 名。对照 h5 语义（`${i18nBase}/${language}.xml` 普通文件），i18nBase 是 **bundle 里的目录**，bundle 名应与包加载同一个 uiBase。同一根因还让 inventory 冒烟页挂死（boot 时系统语言 en ≠ 默认 zh-CN，boot 内 switchBackendLanguage 就炸）。

## 改动

| 文件 | 改动 |
| --- | --- |
| `plugin/framework/backends/cocos/index.ts` | setLanguage 改回从 UI bundle 读翻译：记录 `uiBase`，`bundleReady(uiBase || 'lgui-ui')`，读 `<i18nBase>/<language>` TextAsset |
| `plugin/framework/backends/cocos/platform/index.ts` | loadPackage 校验包归属：自己加载过的记进 `ownPackages`；同名包已存在但不是自己加载的 → 抛 **LGUI-RT-264**（新码），不再静默混用 |
| `plugin/references/error-codes.md` | 新增 LGUI-RT-264（同名界面包被别的来源先加载，FairyGUI 按包名全局注册） |
| `lgui-cocos-mcp/testbed/sync.mjs` | `--conformance` 分支补 `generateTranslations(..., confUi/i18n, ...)`——此前 conf-ui 没有翻译文件，setLanguage 会炸 RT-141 |

## 边界与遗留

- cocos 端真输入（t.click 等）是 T008d 的活（topic 文档已定 CDP 合成触摸方案）；本次验证用 no-op sim 替身把绑定层和语言层跑通，输入位接上后整例应与 headless 完全对齐。
- conf 页面加载时 Cocos 反序列化报 `Sorry, the component of 'DemoEntry' … is corrupted!`（3817）：main.scene 的 DemoEntry 节点挂着已删除的 fork demo 脚本（uuid d87b87ee-…），引擎把组件摘掉，无害但每次构建/加载都报——后续可把该节点清掉（testbed 卫生，不阻塞）。
- FairyGUI 包名全局唯一是平台约束，LGUI-RT-264 把它变成显式错误；一个页面跑两套 LGUI 界面包本来就不受支持。
